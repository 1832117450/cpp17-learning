# Day 006：C++17 工程模块化整理

## 一、今日学习目标

将前几天的独立 C++ 练习整理为可复用的工程模块。

## 二、完成内容

1. 使用 CMake 统一管理程序编译。
2. 创建 include/ 头文件目录。
3. 将 VehicleState 和 ControlCommand 定义在 vehicle.hpp 中。
4. 将 Trajectory 的声明和实现分离。
5. 使用 add_library 创建 planning_core 静态库。
6. 使用 target_link_libraries 链接模块。
7. 为 Trajectory 增加单元测试。
8. 使用 CTest 执行自动化测试。

## 三、关键知识

### 1. 头文件与源文件

.hpp：声明数据类型、类和函数接口。

.cpp：实现具体函数。

### 2. 静态库

planning_core 将轨迹功能封装成可复用模块。

### 3. CMake

add_executable：创建可执行程序。

add_library：创建库。

target_link_libraries：链接依赖库。

### 4. 单元测试

使用 GoogleTest 检查轨迹点数量、数据读取和越界访问。

CTest 负责统一调用已注册的测试程序。

## 四、运行命令

cmake -S . -B build
cmake --build build
./build/day06
./build/run_tests

cd build
ctest --output-on-failure

## 五、今日总结

理解了 C++ 工程的模块化组织方式。

能够区分头文件、源文件、静态库和可执行程序。

后续可以在 planning_core 基础上逐步扩展车辆模型、
轨迹规划及控制模块。
